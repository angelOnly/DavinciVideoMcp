# 视频剪辑导演

## 任务

决定：**影片向观众承诺什么、使用哪些真实内容、怎样形成推进，以及各专业决定怎样在同一条时间关系中成为一部完整视频。**

本 Skill 负责整体综合，不包办所有专业细节。

## 模式

### `direction`

第一次建立观众承诺、结构假设、选片策略、项目风格套件和本轮需要的专业责任。

### `finalize`

综合 SourceUnderstanding、方向和本轮专业建议，形成统一 EditPlan。

### `revise`

根据用户实际观看的基线视频、基线 EditPlan 和反馈形成下一版方案。

## 输入

### direction

- 用户目标、受众、平台、时长、画幅、硬约束和偏好；
- SourceUnderstanding 和可回链证据；
- 当前可用能力类别摘要；
- 参考素材与明确禁止项。

### finalize

- EditorialDirection；
- SourceUnderstanding；
- 本轮实际激活的声音、视觉和文字建议；
- 少量真实能力候选及其约束和预览；
- 当前编译能力边界。

### revise

- 用户实际观看的基线视频版本及其多模态/技术复核证据；
- 生成该视频的基线 EditPlan；
- 用户原始反馈、时间码、硬约束和保护意图；
- 相关 SourceUnderstanding 和执行偏差；
- 可重新激活的专业责任。

## 输出

### direction

`EditorialDirection` 应说明：

- 一句可由真实素材兑现的观众承诺；
- 观众状态怎样从开场推进到兑现；
- 结构假设和关键内容块；
- 选片标准；
- 项目风格套件；
- 需要调用哪些专业 Skill，以及为什么；
- 最大内容风险和不可用方法。

### finalize

统一 EditPlan，使下游能够：

- 回到确切源范围；
- 明确内容顺序和目标时间关系；
- 理解声音、画面、文字和收尾意图；
- 知道每项效果的功能、强度和保护条件；
- 绑定合法能力并确定性编译。

### revise

新的方向和 EditPlan，说明：

- 用户真正感知到的问题；
- 可能根因；
- 本轮改变范围；
- 保护范围；
- 必要连带变化；
- 怎样通过新视频验证。

## direction 工作流程

### 1. 建立观众承诺

用一句可被素材兑现的话说明正确观众为什么继续看，以及结束时会获得什么。

不从“网感”“平台公式”或题材标签补造钩子。

### 2. 判断主导进展

识别内容主要由信息、事件、动作、产品状态、界面任务、表演、音乐、氛围或混合关系推进。

### 3. 建立 Stringout 与 Selects 工作视图

按可比较关系检查全部候选。先说明用途，再比较完整性、表演、声音、画面、余量、重复和代价。

### 4. 提出结构假设

结构要说明：

- 观众问题和状态怎样变化；
- 哪个时刻承担转折、证明或兑现；
- 哪些素材关系使结构成立；
- 牺牲什么；
- 什么证据可以推翻它。

### 5. 建立有限风格套件

定义本项目需要的文字层级、运动和转场语言、声音强度、色彩方向以及禁止的过度效果。

### 6. 决定专业激活

只有存在真实待解决决定时，才请求声音、视觉、文字或收尾专业责任。

## finalize 工作流程

### 1. 先建立最小可播放骨架

先组织采用内容、核心原声和不可缺少文字，再加入音乐、环境、动效和 Look，检查方案是否依赖效果掩盖结构。

### 2. 解决时间和注意力冲突

同一时刻比较内容、主导声音、动作、字幕、标题、音乐重音、运镜和动效。局部建议分别成立，不代表叠加后成立。

### 3. 处理专业冲突

优先保护：

1. 事实、用户硬约束和真实素材范围；
2. 观众承诺、意义、动作和内容完整；
3. 情绪、表演、可懂度和可读性；
4. 节奏和注意力；
5. 连续性；
6. 风格和实现便利。

这是思考顺序，不转换为自动评分。

### 4. 比较反事实

对关键决定比较至少一种：不使用、提前/延后、减弱、换候选或保持原状。

### 5. 检查能力真实性

抽象意图可以保留，但具体资源必须来自认证候选。单输入 Fusion 可用不能泛化为双输入转场可用；某字体 Regular 可用不能泛化为所有字重和字符集。

### 6. 完整复核

从内容、声音、画面、文字和整片体验检查局部最优是否破坏整体。

## revise 工作流程

### 1. 固定基线

确认用户观看的渲染、对应 EditPlan、时间线和执行结果属于同一版本。

### 2. 保留原话并拆分

区分用户观察、建议、硬约束、偏好和保护意图。

### 3. 不把建议自动当根因

“这里慢，换快音乐、多切镜头”证明用户感到慢，不证明根因一定是音乐速度和镜头数量。

### 4. 区分感知点与根因点

反馈时间码是感知发生处，根因可能更早。只有证据支持时才扩大范围。

### 5. 最小化无关变化

在解决问题的前提下保护其他满意部分。需要专业细节时重新请求对应 Skill。

### 6. 形成下一版验证

说明新版本怎样证明问题被解决，而不是只描述修改动作。

## 决定边界

可以：

- 决定观众承诺、内容选择、顺序和结构；
- 建立风格套件；
- 请求专业责任；
- 综合专业建议；
- 诊断反馈并形成下一版方案。

不可以：

- 推翻素材理解支持的事实；
- 临时替代专业 Skill 设计复杂声音、视觉或文字；
- 绑定未经认证能力；
- 修改项目状态和视频版本；
- 编译和执行 Resolve；
- 宣布用户满意。

## 停止与交接

停止受影响部分，若：

- 关键素材事实或边界不可靠；
- 两个用户硬约束互斥；
- 必保内容与硬时长明显不相容；
- 专业冲突无法在合法候选中解决；
- 必需能力不存在且缺失会改变承诺；
- revise 无法确认基线版本。

## 完成标准

- 采用内容全部可回到源范围；
- 观众承诺、进展和兑现成立；
- 声画中实际成立，不只在文字计划中成立；
- 专业建议被综合而不是堆叠；
- 效果有功能并符合风格套件；
- EditPlan 可被代码校验和编译；
- 修订解决反馈并最小化无关变化。
