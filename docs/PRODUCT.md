# DavinciMcp 产品需求

## 1. 产品定义

DavinciMcp 是一套运行在本地剪辑工作站上的专家视频剪辑产品。

用户在 Web 中提交视频、音频、图片、文档、参考素材、项目背景、剪辑目标、风格偏好、硬约束和交付要求。系统通过本地媒体分析、云端多模态证据、Codex 专业 Skills、创意能力库和 DaVinci Resolve，生成可真实播放、能够持续修改的高完成度成片候选。

用户不需要为了完成产品已承诺的操作进入 DaVinci 手工剪辑。用户通过 Web 观看确切视频版本、提交时间码反馈、比较版本，并最终批准母版。

## 2. 产品承诺

首个可用版本的核心承诺是：

> 根据用户真实素材、明确要求和当前工作站已经验证的创意能力，自动生成具有专业审美、可持续修改的高完成度成片候选。

成片候选应在当前项目需要且能力可用的范围内，尽可能完成：

- 内容选片、结构、顺序和切点；
- 字幕、标题、人物条和必要信息文字；
- 音乐、音效、环境声和声音连接；
- 构图、横竖屏重构、数字运镜、转场、动态图形和 VFX；
- 对白层级、基础混音、镜头校正、镜头匹配和整体 Look；
- 实际 Resolve 时间线、真实渲染、技术检查和内部完整成片复核。

产品不宣称一次生成必然让所有用户满意。用户可以针对 v1 继续生成 v2、v3；用户明确批准的版本才成为最终母版。

## 3. 三种视频结果

### 3.1 内部工作版

系统为验证结构、声画、效果和执行结果生成的中间渲染。它可以在本次运行中继续修改，默认不要求用户审核。

### 3.2 成片候选

已经经过内容、声音、视觉、文字、收尾和技术验证，足以让用户正常观看并判断是否满意的用户可见版本。

成片候选一经发布即不可覆盖。

### 3.3 批准版本与交付母版

用户明确接受的成片候选。系统从该版本生成最终母版和纯技术派生规格。

仅改变编码、码率或分辨率的输出属于技术派生；需要重新构图、重新排版或改变内容关系的横竖版转换属于新的创意版本。

## 4. 目标用户与优先场景

产品面向：

- 有真实素材和明确内容目标，但不希望学习 DaVinci 操作的创作者；
- 需要提高从素材到成片效率，同时保留最终审美决定权的内容团队；
- 希望使用自然语言持续修改视频，并保留历史版本的用户；
- 希望把专业剪辑方法、外部素材能力和 Resolve 自动执行形成稳定工作流的研发团队。

首期优先通过真实项目验证：

- 口播、采访、知识、资讯和教程；
- 产品展示、屏幕操作和说明视频；
- 由视频、图片、对白、音乐、音效和标题组成的短视频；
- 需要少量调色、动效、运镜和多画幅适配的内容。

动作、舞蹈、音乐驱动、剧情和高度依赖表演反应的项目可以进入系统，但只有完成真实闭环并达到验收标准后，才声明为稳定支持场景。

## 5. 用户输入

### 5.1 项目素材

用户可以提供：

- 视频；
- 独立音频；
- 图片、图标和图表；
- 文稿、脚本、产品资料和事实说明；
- 参考视频、参考图片和品牌资料；
- 必须保留、不得使用或只能作为参考的内容说明。

每份素材允许用户标注角色，例如主素材、补充画面、采访、屏幕录制、背景音乐、音效、参考或不得使用。

### 5.2 项目简报

Web 至少允许用户说明：

- 视频要解决的问题和目标观众；
- 希望观众看完后知道、相信、感到或完成什么；
- 目标平台、画幅、时长和语言；
- 必须出现、不得出现和不能改变的内容；
- 风格偏好、参考和明确禁止项；
- 字幕、标题、音乐、音效、动效、调色和交付要求；
- 是否允许将必要分析代理上传至云端多模态服务。

用户点击“开始制作”后，系统冻结本次运行输入。用户之后修改项目草稿不会悄悄改变正在运行的任务；需要采用新输入时创建新的运行。

## 6. 素材上传、校验与提交门禁

### 6.1 素材状态

用户上传的每个素材只使用四种面向 Web 的状态：

- `uploading`：文件仍在上传；
- `validating`：服务端正在验证；
- `ready`：可以进入本次任务，可附带非阻断警告；
- `invalid`：不能用于任务，必须替换、重新上传或移除。

浏览器可以做文件大小、扩展名、空文件和重复选择等快速预检，但只有服务端验证结果具有权威性。

### 6.2 服务端必须验证

上传完成后，系统必须检查：

- 文件完整、可访问且内容哈希能够稳定计算；
- 存在与素材角色匹配的可解码音频、视频或图片内容；
- 时长、分辨率、帧率、时间基准、旋转和音视频流能够读取；
- 开头、中间和结尾能够实际解码；核心源视频按实现策略完成更完整的错误扫描；
- 时间轴能够稳定定位；若不能，系统能否生成稳定工作副本并建立时间映射；
- 文件不是尚未本地化的云盘占位文件；
- 校验期间源文件没有发生变化。

### 6.3 自动修复与警告

以下问题若能够可靠生成稳定工作副本，不应直接要求用户重新上传：

- 可变帧率；
- 不稳定时间戳；
- Resolve 不适合直接使用的编码；
- 需要标准化的旋转、采样率或像素格式。

以下问题通常只显示警告：

- 分辨率低于目标输出；
- B-roll 没有音轨；
- 横屏素材将用于竖屏项目；
- 曝光、噪声、响度或色彩信息较差；
- 文件很大，预计分析时间较长。

### 6.4 禁止提交的情况

出现以下情况时，素材必须为 `invalid`，并阻止使用它提交任务：

- 上传未完成或文件无法访问；
- 必需媒体流不存在或无法解码；
- 时长为零、文件严重损坏或受保护；
- 时间轴无法可靠定位且不能生成稳定工作副本；
- 用户要求使用音频，但文件实际上没有可用音轨；
- 文件在校验后发生变化或被删除。

Web 必须显示可操作原因，例如“视频在 00:02:14 附近无法解码，请重新导出或替换”，不能只显示笼统失败。

### 6.5 “开始制作”启用条件

只有同时满足以下条件，Web 才允许开始任务：

- 至少存在一个有效主素材；
- 所有本次勾选使用的素材均为 `ready`；
- 没有素材仍处于 `uploading` 或 `validating`；
- 所有 `invalid` 素材已经替换或从本次任务移除；
- 必填项目配置已经完成；
- 本次任务必需的系统能力健康检查通过。

提交时系统再次确认素材仍存在、内容哈希未变化、稳定工作副本仍可用，然后冻结本次运行输入。

## 7. Web 产品功能

### 7.1 项目列表

显示项目、最近成片候选、当前任务状态和需要用户处理的事项。

### 7.2 项目创建与素材工作区

支持：

- 选择或上传本地素材；
- 显示上传、校验和分析进度；
- 显示阻断错误、自动修复结果和非阻断警告；
- 替换、重新上传或移除不可用素材；
- 设置素材角色、顺序、说明和使用限制；
- 编辑项目简报与交付要求；
- 查看云端分析授权范围；
- 只有提交门禁通过时启用“开始制作”。

### 7.3 任务与进度

用户可以看到：

- 当前正在处理的阶段；
- 已完成的关键步骤；
- 当前是否在等待用户、外部模型或 Resolve；
- 为什么停止以及下一步需要什么；
- 对应的 Codex 委托线程及关键消息。

Web 展示产品工作流事实，不把 Codex turn 状态直接当成项目状态。

### 7.4 视频审核

审核页必须提供：

- 真实可播放成片候选；
- 时间码定位；
- 自然语言反馈；
- 对某一时间范围的批注；
- “这里之外不要改”等保护意图；
- 当前版本所使用的重要能力和已知限制披露；
- 接受版本、继续修改或取消任务。

### 7.5 版本比较

支持在 v1、v2、v3 之间切换，查看每一版解决了什么反馈以及哪些部分被保护。首版采用线性版本，不实现通用分支图。

### 7.6 最终交付

用户批准某一成片候选后，可以生成已经验证的母版和技术派生规格，并查看输出路径和验证结果。

## 8. Codex 委托与线程

- 一项独立剪辑委托对应一条持久 Codex 主线程；
- 同一委托的用户反馈和下一版修改在原线程中启动新的 turn；
- 同一项目若存在互不相同的独立委托，可以拥有不同线程；
- 素材分析、计划编译、Resolve 执行和技术验证不因内部步骤而创建大量用户可见线程；
- Codex Thread 用于专业工作上下文和用户可见交流，不拥有项目、版本和执行状态；
- Codex 暂时不可用时，用户仍可查看项目、素材、历史视频和反馈，任务等待恢复而不是丢失状态。

## 9. 完整产品流程

### 阶段 A：创建与验证委托

1. 用户创建项目、上传素材和填写简报；
2. 系统完成服务端素材校验，用户替换或移除不可用文件；
3. 所有提交门禁通过后，用户开始制作；
4. 系统再次核验文件身份，冻结运行输入并创建或恢复 Codex 委托线程。

### 阶段 B：媒体与素材证据

5. 系统复用上传校验结果，生成必要代理、转写、镜头边界、抽帧、节拍、响度、静音和多模态证据；
6. 对证据不足或矛盾的范围补充更密集分析。

### 阶段 C：专业剪辑计划

7. 调用 `video-source-understanding` 建立可回链的素材理解；
8. 调用 `video-edit-director` 的 `direction` 模式建立观众承诺、结构假设、选片策略和项目风格套件；
9. 根据真实任务按需调用声音、视觉和文字专业 Skill；
10. 调用 `video-edit-director` 的 `finalize` 模式形成统一 EditPlan。

### 阶段 D：能力检索、绑定与内部工作版

11. 系统根据计划的创意意图，对认证素材目录执行结构化过滤、全文检索和可选语义召回；
12. 只向相应专业 Skill 返回少量真实候选及预览，完成审美选择；
13. 系统把选中的能力本地化、校验并形成 CapabilityBinding；
14. 确定性代码校验 EditPlan 并编译 ResolveExecutionPlan；
15. `davinci-engine-mcp` 在隔离的新工作时间线中执行、读回并渲染内部工作版。

### 阶段 E：收尾与成片候选

16. 系统对内部工作版进行技术检查和多模态音视频复核；
17. 调用 `video-finishing-designer`，必要时重新调用声音、视觉或文字 Skill，形成一次有界的收尾调整；
18. 系统应用调整、再次读回并渲染；
19. 技术验证通过后发布成片候选 v1。

### 阶段 F：用户反馈与新版本

20. 用户针对确切 v1 提交反馈；
21. 调用 `video-edit-director` 的 `revise` 模式诊断反馈，并按需重新调用专业 Skill；
22. 系统生成新的计划、新 Resolve 时间线和成片候选 v2；
23. v1 保持不变。

### 阶段 G：批准与交付

24. 用户批准某个版本；
25. 系统从批准版本生成母版和已经验证的交付规格。

## 10. Skills 调用表

| 产品节点 | 调用 Skill | 调用条件 | 结果用途 |
|---|---|---|---|
| 媒体证据准备完成 | `video-source-understanding` | 有新素材、素材替换或理解需要重做 | 建立 SourceUnderstanding |
| 素材理解完成 | `video-edit-director` / `direction` | 每次新委托 | 建立 Editorial Direction 和专业任务需求 |
| 方向已建立 | `video-sound-rhythm-designer` | 存在音乐、音效、对白、节奏或声音连续性决定 | 提供声音与节奏建议 |
| 方向已建立 | `video-visual-designer` | 存在构图、coverage、运镜、转场、动效或画幅决定 | 提供视觉建议和能力需求 |
| 方向已建立 | `video-typography-designer` | 存在字幕、标题、人物条、数据、版式或文字运动决定 | 提供文字建议和能力需求 |
| 专业建议齐备 | `video-edit-director` / `finalize` | 每次生成新成片候选 | 形成统一 EditPlan |
| 内部工作版渲染完成 | `video-finishing-designer` | 需要混音、镜头匹配、Look 和最终文字精修 | 形成收尾调整 |
| 用户反馈某一版本 | `video-edit-director` / `revise` | 生成下一版 | 形成修订方向和新的 EditPlan |

Skills 不互相启动。唯一调用者是工作流编排器。

## 11. 创意能力库

### 11.1 能力类别

产品允许接入并认证：

- 音乐、音效、环境声；
- MP4、MOV、PNG、透明叠加和图形素材；
- 字体、标题、字幕样式和人物条；
- Fusion 效果、转场、生成器和 Motion Graphics；
- 静态重构图、关键帧运镜和可复用 Motion Recipe；
- LUT、PowerGrade、DCTL、OpenFX；
- Fairlight 效果链、VST 和声音处理预设。

### 11.2 运行原则

- 原始采购包保存在外部素材库，不直接等于产品能力；
- 资源必须拆成用途明确的原子能力；
- 大型文件不存进 SQLite，数据库只保存元数据、索引和文件引用；
- 每项能力必须通过发现、部署、执行、读回和真实渲染测试；
- 能力约束必须明确画幅、输入端口、字体字重、字符集、插件依赖和版本；
- 每个项目先建立有限风格套件，再从少量候选中选择；
- Codex 和 Skills 不读取整个素材库，只接收检索后的候选、预览和约束；
- 被选中的云端资源必须先下载到本地受管缓存并校验内容哈希，再交给 Resolve；
- 没有叙事、注意力、节奏、连续性或信息功能的效果不使用；
- 能力缺失且会明显降低结果时，不静默替换成相似模板，应说明取舍并等待决定。

完整存储、认证和检索方案见 `CREATIVE_LIBRARY.md`。

## 12. 版本与反馈规则

- 用户可见视频版本不可覆盖；
- 每个版本对应确切渲染、计划基线和 Resolve 时间线；
- 每条反馈必须绑定用户实际观看的版本；
- 时间码表示用户感知问题的位置，不自动等于根因位置；
- 修订优先解决反馈并最小化无关变化；
- 用户要求保护的区域，除非存在必要连带变化，否则不得修改；
- 任何必要连带变化都必须在新版本说明中披露。

## 13. 技术与审美验证边界

### 技术验证由代码负责

例如：

- 用户上传素材是否可读、可定位、可稳定处理；
- 时长、轨道、时间范围和画幅是否符合计划；
- Resolve 写入是否真实存在；
- 渲染是否成功；
- 是否有黑帧、静音、离线媒体或明显规格错误；
- 响度和峰值是否符合明确交付要求。

### 审美判断由专业 Skills 和用户负责

系统可以判断拖沓、注意力冲突、音乐抢对白、字幕负担、转场过度和风格不一致，并在用户看到之前做一次有界调整，但不能输出一个“审美通过分数”替代用户观看。

最终接受权始终属于用户。

## 14. 首个可用版本范围

必须具备：

- 本地单用户 Web；
- 多项目、素材上传、服务端校验和提交门禁；
- 持久 Codex 委托线程；
- 本地 FunASR 中文转写；
- 镜头检测、抽帧和确定性音频分析；
- 通过 OpenAI-compatible Adapter 调用配置模型 `gemini-3.5-flash`，并在启动时探测其图片、音频、视频和结构化输出能力；
- 六个专业 Skills；
- Nextcloud 原始采购库、认证素材库、SQLite 素材目录、全文检索和本地受管缓存；
- 可替换的语义索引接口；是否启用向量召回由认证素材规模和真实检索效果决定；
- 创意能力目录和经过认证的基础适配器；
- 确定性 EditPlan 校验和 Resolve 编译；
- 自研 `davinci-engine-mcp`；
- 新时间线执行、写后读回和真实渲染；
- 高完成度 v1；
- 绑定 v1 的反馈和不覆盖旧版的 v2；
- 用户批准和母版输出；
- 中断恢复与 Resolve 写入结果未知对账。

首期不为以下假设预建复杂结构：

- 多用户协作和权限系统；
- 云端集群和多机渲染；
- 通用分支版本图；
- 任意 NLE 抽象；
- 无限制插件市场；
- 自动安装未知 EXE、DLL、OFX 或未经验证模板；
- 让模型直接执行任意 Lua；
- 对所有视频类型宣称同等质量。

## 15. 首个可用版本验收

至少使用两个真实项目完成：

1. Web 上传素材，服务端发现一个不可用文件并阻止提交；用户替换或移除后才能开始；
2. 生成可回链的转写、镜头、图片、音频和多模态证据；
3. 形成专业 EditPlan；
4. 从素材目录检索少量候选，并使用至少一种音乐/音效、一种视觉或文字能力和一种基础收尾能力；
5. 选中资源从 Nextcloud 本地化到受管缓存并通过内容校验；
6. 在 Resolve 中创建新时间线并真实渲染 v1；
7. 验证时间线与计划一致；
8. 用户针对 v1 提交反馈；
9. 生成不覆盖 v1 的 v2；
10. v2 真实解决反馈且无明显无关破坏；
11. 用户可以批准某版并生成母版；
12. 模拟应用、Worker 或 MCP 中断后能够恢复；
13. 模拟一次外部写入结果未知，系统先对账而不是重复写入；
14. 反代模型能力探测结果与实际启用的多模态模式一致，不虚报视频理解能力。

## 16. 产品决策原则

- 优先满足当前明确需求的最简单、可靠、可维护方案；
- 不因“未来也许需要”增加对象、状态、服务和抽象；
- 简单方案存在明确代价、复杂方案明显更臃肿时，在开发前向产品负责人说明取舍；
- 未经真实项目和实机测试证明的能力，不进入产品承诺；
- 新功能应尽可能只增加新的能力适配、编译映射、检索实现或条件工作流步骤，不破坏核心项目、版本和反馈链路。
