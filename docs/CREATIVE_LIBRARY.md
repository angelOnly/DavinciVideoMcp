# 创意素材库、目录与检索

## 1. 目标

创意素材库解决三个问题：

1. 大量 DaVinci 素材如何长期保存，而不占满工作盘；
2. 系统如何知道每个素材能做什么、适合什么、有哪些技术约束；
3. Codex 和专业 Skills 如何只看到少量合适候选，而不是阅读数千个文件。

本方案采用：

> **Nextcloud 保存文件，SQLite 保存目录元数据和全文索引，本地内容寻址缓存供 Resolve 使用，可选语义向量索引负责语义召回。**

任何大型媒体、模板、字体、模型和预览文件都不保存进 SQLite。

## 2. 四层素材空间

### 2.1 原始采购库

默认配置：

```text
C:\Users\13222\Nextcloud\达芬奇素材
```

保存：

- 购买的原始 ZIP、文件夹和安装包；
- 未解压或未验证的完整素材包；
- 原始说明、授权文件和卖家文档；
- 仅用于保留来源的备份。

原始采购库不直接供自动剪辑使用。系统不批量改名、不假设整包可用，也不让 Resolve 直接读取在线占位文件。

### 2.2 Testing 工作区

本机临时目录，用于：

- 解压一个选定素材包；
- 拆分原子资源；
- 安全扫描；
- 技术探测；
- Resolve 安装、调用和实际渲染；
- 生成人工审核预览。

Testing 内容可以清理，不作为长期权威文件。

### 2.3 认证素材库

建议新建：

```text
C:\Users\13222\Nextcloud\达芬奇认证素材库
```

只保存已经：

- 拆分为原子资源；
- 使用稳定命名；
- 生成预览；
- 明确技术约束；
- 通过实机认证；
- 获准进入自动工作流；

的素材。

推荐结构：

```text

│   ├── sound-effects/
│   └── ambience/

│   ├── backgrounds/

│   └── elements/
├── fusion/
│   ├── titles/
│   ├── effects/
│   ├── transitions/
│   └── generators/
├── motion/
├── color/
│   ├── luts/
│   ├── looks/
│   └── powergrades/
├── fonts/
├── previews/

```

目录用于人工管理，不作为业务合同。系统使用稳定 `capability_id`、内容哈希和 Catalog 记录识别能力，不能依赖中文文件夹名称作唯一身份。

### 2.4 项目内内容寻址缓存

Resolve 只使用本地真实文件，不直接使用 Nextcloud 占位路径。

缓存统一放在当前工程根目录的 `workspace` 下：

```text
<project-root>/workspace/creative-cache/objects/<content-hash>
```

`<project-root>` 指包含 `AGENTS.md`、`README.md` 和项目代码的工程根目录。相对路径必须按工程根目录解析，不能依赖进程启动时的当前工作目录。首期不把应用管理的缓存写到工程目录外部。

缓存职责：

- 把选中的认证资源从 Nextcloud 本地化；
- 校验内容哈希；
- 使用稳定短路径供 Resolve 调用；
- 在活动任务期间锁定；
- 按容量和最近使用清理非锁定对象；
- 避免同一文件重复复制。

## 3. 数据库边界

### 3.1 `creative_catalog.db`

数据库统一放在当前工程根目录的运行工作区：

```text
<project-root>/workspace/data/creative_catalog.db
```

工程根目录应位于本机普通目录，不应放在 Nextcloud 同步目录中。

保存概念信息：

- 能力身份和显示名称；
- 素材类别和实现机制；
- 内容哈希和存储引用；
- 技术信息；
- 能力描述、适用场景和禁用场景；
- 风格、情绪、强度和注意力特征；
- 画幅、时长、语言、字符集和输入端口约束；
- Resolve、插件、字体和系统依赖；
- 认证状态与实测环境；
- 预览、缩略图、波形、前后对比等引用；
- 历史使用结果和渲染成功记录；
- FTS 索引内容；
- 可选语义索引中的向量记录引用。

不保存文件本体、模型权重或大型 BLOB。

### 3.2 可重建原则

Catalog 是认证素材库的本地目录与索引，不是唯一文件真相。

必须支持：

```text
认证素材库 + sidecar manifest + 预览
→ 重建 creative_catalog.db
→ 重建全文和语义索引
```

项目业务数据库只保存已经绑定到版本的：

- `capability_id`；
- 内容哈希；
- 本地缓存身份；
- 当时使用的约束与参数快照。

Catalog 后续更新不能改变历史视频版本使用的确切能力事实。

## 4. 原子能力

一个采购文件夹不等于一个能力。

原子能力是可以被独立描述、选择、部署、执行和验证的最小资源，例如：

- 一首音乐；
- 一个 Whoosh 音效；
- 一个透明叠加 MOV；
- 一个标题模板；
- 一个 Fusion 片段效果；
- 一个 LUT；
- 一个字体字重和字符集能力；
- 一个 Motion Recipe；
- 一条音频处理链。

每个原子能力必须有明确机制类型。禁止使用一个笼统“运镜模板”同时混合：

- Transform 关键帧；
- Fusion 模板；
- OpenFX 插件；
- 预渲染叠加视频。

不同机制由不同 Adapter 管理。

## 5. 上架与认证流程

```text
扫描原始采购库
→ 选择一个素材包
→ 解压到 testing
→ 拆分原子资源
→ 技术探测和依赖识别
→ 生成标准预览
→ 自动生成初步描述和标签
→ 人工校正关键语义
→ Resolve 部署与执行测试
→ 写后读回
→ Golden Render
→ 记录约束
→ 复制到认证素材库
→ 写入 Catalog
→ 更新 FTS/语义索引
```

### 5.1 自动描述不能直接成为真相

模型可以为素材生成：

- 功能描述；
- 风格、情绪和强度候选；
- 可能适用的场景；
- 画面或声音的可观察特征；
- 初步关键词。

但以下信息必须由代码或人工确认：

- 文件格式和内容哈希；
- 时长、分辨率、声道、透明通道；
- Fusion 输入输出节点；
- 可修改参数；
- 字体字重和中文覆盖；
- 插件和版本依赖；
- 横竖屏行为；
- 真实渲染是否正确；
- 是否允许进入自动链路。

### 5.2 标准预览

不同素材使用统一测试场景：

| 类别 | 预览要求 |
|---|---|
| 标题/人物条 | 固定中英文测试文本，横屏与竖屏渲染 |
| 转场 | 标准 A/B 片段，展示真实时长和边界 |
| LUT/Look | 人物、产品、灰阶和色卡的前后对比 |
| 字体 | 中文、英文、数字、标点、Regular/Bold 样张 |
| 音效 | 试听文件、波形、时长、响度和尾音 |
| 音乐 | 代表片段、能量曲线、结构和可裁切位置 |
| Fusion 效果 | 标准片段实际渲染，显示公开参数 |
| 透明叠加 | 黑底、白底和真实视频叠加预览 |
| Motion Recipe | 主体居中和偏置两种素材上的运动演示 |

Skills 应观看或试听真实预览，不能根据文件名选择。

## 6. 认证状态

只保留：

- `testing`：正在测试，不能进入项目执行；
- `certified`：可以自动使用，但受明确约束；
- `manual_only`：可人工使用，不进入无人工作流；
- `unsupported`：不使用。

运行时只召回 `certified`。

认证合同：

1. 可发现；
2. 可部署或本地化；
3. 可执行；
4. 可读回；
5. 可真实渲染。

单个资源通过不能泛化到同目录所有资源。

## 7. 素材描述维度

Catalog 至少能表达以下概念，不要求 Markdown 固定全部字段：

### 7.1 功能

例如：

- 关键词强调；
- 人物身份介绍；
- 段落过渡；
- 冲击落点；
- 情绪上升；
- 屏幕指向；
- 产品高光；
- 空间连接；
- 时间压缩；
- 画面质感塑造。

### 7.2 适用场景

例如：

- 口播；
- 采访；
- 产品展示；
- 教程；
- Vlog；
- 科技；
- 商业；
- 情绪短片；
- 新闻资讯。

### 7.3 审美属性

例如：

- 克制 / 强烈；
- 现代 / 复古；
- 商业 / 纪录；
- 精确 / 手绘；
- 温暖 / 冷峻；
- 柔和 / 冲击；
- 高信息密度 / 低注意力负担。

### 7.4 约束

例如：

- 支持画幅；
- 可伸缩时长；
- 可修改文字、颜色和位置；
- 字体和字符集；
- 输入端口；
- 透明通道；
- 目标轨道；
- Resolve 版本；
- 插件依赖；
- 不适用场景。

## 8. 混合检索

Codex 和 Skills 不读取全量目录。系统从创意意图中构建查询，按以下顺序处理。

### 8.1 结构化硬过滤

先排除：

- 非目标能力类别；
- 非 `certified`；
- 不兼容当前画幅、语言、字符集或 Resolve 版本；
- 缺失插件、字体或输入端口；
- 不支持要求时长；
- 与用户明确禁止项冲突；
- 不属于当前项目风格套件；
- 当前机器无法部署或本地化。

硬约束不能被语义相似度覆盖。

### 8.2 FTS5 全文召回

在以下文本中检索：

- 名称；
- 功能说明；
- 适用与禁用场景；
- 风格、情绪和强度；
- 人工标签；
- 自动描述中经确认的内容。

FTS5 是首期必需能力，即使向量索引关闭，系统仍能工作。

### 8.3 语义向量召回

`SemanticIndexPort` 用于理解自然语言意图，例如：

> 克制但有力量的科技感关键词标题，适合人物观点落下时出现，不要像游戏宣传片那样夸张。

向量内容来自 Catalog 的语义摘要，而不是把全部原始媒体直接嵌入。

首个后端可以使用本地嵌入式向量索引；具体实现不进入业务合同。只有以下任一条件成立时才要求启用：

- 认证目录规模已经使 FTS 召回明显不足；
- 真实检索评测证明语义召回显著提高候选质量；
- 项目需要大量跨语言或模糊风格搜索。

没有向量索引时，系统不得中断，只降低语义召回能力并记录模式。

### 8.4 重排

候选根据以下因素重排：

- 硬约束匹配度；
- 文本和语义相关性；
- 当前项目风格一致性；
- 是否与本片其他效果重复；
- 历史 Golden Render 和项目成功率；
- 用户过往接受或拒绝的风格；
- 本机是否已缓存或部署；
- 注意力预算与效果强度。

### 8.5 返回候选

只向专业 Skill 返回 5～10 个候选，每个候选包含：

- 能力 ID；
- 简短功能和风格说明；
- 关键约束；
- 真实缩略图、短视频或音频试听；
- 不能使用的场景；
- 当前本地化/部署状态。

Skill 负责审美比较，代码负责最终可执行性确认。

## 9. 查询与选择边界

```text
EditPlan 中的创意意图
→ Creative Resolver 构造查询
→ 混合检索返回少量候选
→ 对应专业 Skill 观看/试听并选择
→ 系统再次验证
→ 本地化并形成 CapabilityBinding
```

Skill 不返回任意文件路径，也不直接选择 Nextcloud 文件名。

CapabilityBinding 必须冻结：

- `capability_id`；
- 内容哈希；
- 认证版本；
- 本地缓存对象；
- 实际参数；
- 当时适用的约束。

## 10. Nextcloud 本地化

### 10.1 占位检测

系统必须识别：

- 文件是否仅为在线占位；
- 是否正在同步；
- 是否已完整下载；
- 下载后大小和哈希是否稳定。

### 10.2 本地化流程

```text
候选最终选中
→ 请求 Nextcloud 将文件保留在本机
→ 等待下载完成
→ 计算并核对内容哈希
→ 放入内容寻址缓存
→ 记录缓存对象和锁
→ Resolve 使用缓存路径
```

下载失败、哈希变化或文件仍为占位时，能力绑定失败，不能静默使用别的资源。

### 10.3 缓存清理

- 活动任务、已提交执行计划和正在渲染的资源必须锁定；
- 用户版本仍需复现时，保存内容哈希和可重新本地化来源；
- 非锁定资源按容量、最近使用和重新下载成本清理；
- 清理缓存不删除 Nextcloud 认证源，不修改 Catalog 身份；
- 项目需要重渲染时，系统按哈希重新本地化。

## 11. 素材库与 Resolve 部署

不是所有认证资源都需要永久安装到 Resolve。

### 11.1 运行时媒体

WAV、MP3、MP4、MOV、PNG 等：

- 只需本地化到缓存；
- 按项目导入媒体池；
- 不需要全局安装。

### 11.2 安装型资源

字体、LUT、Fusion 模板和插件：

- 通过受控管理员流程部署；
- 记录部署版本和本机库存；
- 项目开始前执行部署预检；
- 未部署或版本不匹配时不进入候选；
- 未知 EXE、DLL、OFX 不自动安装。

`davinci-engine-mcp` 只读取已经绑定并本地可用的能力，不承担整个素材市场的搜索。

## 12. 数据一致性与备份

- `creative_catalog.db` 位于 `<project-root>/workspace/data/`，工程根目录不放进 Nextcloud 同步目录；
- 可定期导出一致性快照、manifest 和索引版本到 Nextcloud；
- 原始采购库和认证素材库由 Nextcloud 保存文件；
- Catalog 可从认证库重建；
- 语义向量索引可从 Catalog 重新生成；
- 项目历史保存确切能力哈希，不依赖 Catalog 当前描述；
- 文件被替换时产生新内容身份，不能原地改变历史能力。

## 13. 首期实现范围

本次开发必须实现：

- 原始采购库和认证素材库路径配置；
- Catalog 扫描与原子能力登记；
- 大文件不入库；
- 认证状态和真实预览引用；
- 结构化过滤；
- SQLite FTS5；
- 候选限制与预览交付；
- Nextcloud 本地化、哈希校验和本地缓存；
- CapabilityBinding；
- 已实测基础 Adapter 的目录接入。

`SemanticIndexPort` 必须定义，但向量后端是否在首条闭环中启用，由首批认证素材规模和检索评测决定。不能因为未来目录会变大就提前搭建独立向量服务。

## 14. 验收

至少验证：

1. 原始采购包不会自动进入候选；
2. 一个素材包可以拆分并认证至少三个原子能力；
3. Catalog 中只有元数据和引用，没有媒体 BLOB；
4. 结构化过滤能排除画幅、插件、字体和认证状态不匹配的资源；
5. FTS 可以按功能、场景和风格找到候选；
6. 启用语义索引时，不改变候选合同和上层调用；
7. Skill 只收到少量候选和真实预览；
8. Nextcloud 在线占位文件不能直接进入 Resolve；
9. 资源本地化后哈希一致，活动任务期间不会被清理；
10. 删除本地 Catalog 或向量索引后可以从认证库重建。
